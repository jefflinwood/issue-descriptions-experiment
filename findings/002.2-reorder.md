# Finding — reorder a past order (protocol 002.2)

Collected 2026-11-21, 17:14–19:33 UTC, in `results/main-003` (protocol `002.2`, hash
`5e884cf1aeb7519f`). 80 of 80 scheduled attempts completed. There were no timeouts,
setup or infrastructure failures, replacements, subagent use, or out-of-scope changes.
This is exploratory evidence from one task with five repeats per cell.

## How to read the results

- **Primary result: the corrected evaluation.** After collection, the study owner
  decided to report the corrected evaluation as primary and the frozen evaluation as
  preliminary. The experiment measures issue writing. Three frozen checks were found
  to penalize analysis choices rather than behavior the descriptions asked for, so
  those errors should not count against the descriptions.
- **The corrections were defined after seeing the data.** Each one is described
  below with its evidence. Each re-examines only attempts that a flawed check failed,
  and leaves every other criterion at its frozen result. No saved record was
  modified. The corrected numbers are reproduced by
  [`002.2-reorder/posthoc.py`](002.2-reorder/posthoc.py); per-attempt evidence is in
  [`002.2-reorder/posthoc.json`](002.2-reorder/posthoc.json).
- **The corrections can only raise scores.** They were prompted by inspecting
  failures. Passing checks were validated by the negative controls before collection,
  but not re-inspected attempt by attempt.

## Design

- **Task:** *“Let customers reorder a past order.”* At the pinned Ridgeline commit
  there is no reorder feature and no client-side feature that overlaps it.
- **Descriptions:**
  - **D1:** the one-line request.
  - **D2:** the request plus the approved product decisions.
  - **D3:** D2 plus 11 examples, repository entry points, constraints, and
    verification guidance.
  - **D4:** every D3 fact inside a realistic, noisy issue thread, with an abandoned
    one-click idea, two decisions reversed later in the thread, declined scope creep,
    and chatter.
- **Configurations:**
  - Codex CLI 0.171.0 with `gpt-6.1-terra` and `gpt-6-luna` (reasoning medium).
  - Claude Code 2.1.330 with `claude-sonnet-5-5` and `claude-haiku-5-5` (effort
    medium).
- **Schedule:** 5 randomized complete blocks gave 80 sequential attempts. Each was a
  fresh session in a Seatbelt sandbox, evaluated in a clean checkout against hidden
  fixtures.
- **Primary success:** a completed session, all contract criteria AC01–AC10, and the
  original regression suite.
- **Minimal outcome:** a working reorder that never crosses accounts. It is meant to
  be fair to every description, including D1.

## What the results show

1. **Writing down the decisions is what matters, not detail or tidiness.** Success
   jumps from D1 (3/20) to D2 (17/20). Adding examples, entry points, and
   verification guidance (D3) does not improve on D2 here. Most D1 failures are
   choices the request never specified, for example:
   - offering Reorder only to customers, a fair reading of “let customers reorder”;
   - not carrying over the shipping method;
   - placing the order in one click instead of prefilling the form.

   The minimal outcome stays high under D1 (18/20). Agents built a working reorder,
   just not the one the stakeholders wanted.
2. **Sonnet already made the stakeholders' choices on D1 (3/5).** The other three
   configurations scored 0/5 on D1.
3. **A messy issue did not hurt.** D4 (18/20) matched or beat D3 (17/20). No D4 attempt
   followed a superseded comment: none placed the order in one click, and none copied
   the dates (AC02 and AC06 passed in all 20 D4 attempts).
4. **Access control held everywhere.** No attempt in any condition let a customer see,
   reorder, or affect another account's order. MIN-AUTH and AC03's cross-account test
   both passed 80/80.
5. **The remaining D2–D4 failures are real integration bugs the agents' own tests
   missed.**
   - **Unsubmittable reorder form (8 attempts: haiku 3, luna 3, sonnet 2; terra 0).**
     The agent added a GET-only `/orders/<id>/reorder` route that renders the existing
     new-order form. That form has no `action`, so a browser submits it back to the
     same URL and gets *405 Method Not Allowed*. Each of these agents tested by
     posting directly to `/orders/new`, so its tests passed while a real user could
     not place the order.
   - **Crash without a due date (luna D2, 1 attempt).** Submitting the reorder form
     without a due date re-renders the page and raises a template error (HTTP 500).
6. **The original test suite has a blind spot.** One D1 attempt (`035-b3-luna-d1`)
   un-indented a single `return`, which made every new-order submission redisplay the
   form. Nobody could place any order. Ridgeline's 22 original tests passed, because
   none submits the new-order form. Only the hidden acceptance check that submits a
   reorder caught it.
7. **Effort varies far more by configuration than by description.**

   | Configuration | Median agent time | Median input tokens (incl. cached) | Median output tokens | Median tool calls |
   |---|---|---|---|---|
   | sonnet | 40 s | 84k | 5.2k | 5 |
   | terra | 70 s | 176k | 3.0k | 6 |
   | luna | 87 s | 267k | 3.7k | 12 |
   | haiku | 94 s | 473k | 18.7k | 17 |

   Claude Code's own cost estimate for its 40 attempts totals $2.90. That is a CLI
   estimate under subscription access, not an observed charge. Codex reports no cost.

## Limits

- **Small sample.** One task, one host, five repeats per cell. Differences of one or
  two attempts between cells, including D3 vs D4, are within noise.
- **Configurations, not models.** Cross-provider differences include harness
  behavior (system prompts, tools, context management), not only model quality.
- **Post-hoc corrections.** See *How to read the results*. A future protocol version
  should freeze the corrected checks before collection.
- **Sandbox network.** The Seatbelt sandbox cannot filter network traffic by hostname,
  so general HTTPS egress stayed reachable during agent sessions.

## Recommended changes for the next protocol version

1. Freeze checks C1–C3 as corrected. Widen the unavailable-message and README
   patterns, or move README wording to human review.
2. Keep the browser-faithful form submission. It is what exposed the 405 integration
   bug, and it is a useful teaching example: agents' tests posted straight to the
   handler, while users submit through the page.
3. Consider adding an order-creation test to the evaluation regression gate, since the
   original suite cannot detect a broken new-order form.
