# Introductory finding — URL order search (protocol 002.1)

Collected 2026-11-21, 13:18–15:28 UTC, in `results/main-002` (protocol hash
`205b9bdeb7fcbc00`). The workload is archived in `benchmark/archive/002.1-url-search/`.
This is an **introductory, exploratory result**. The task was then retired because
Ridgeline's existing DataTables browser search made the vague request ambiguous in
ways that confound the description treatments (see *Why the task was retired*).

## Design

One Ridgeline issue, *“Let people search the orders list using a shareable URL.”*
Four descriptions: D1 vague, D2 clarified, D3 agent-ready, D4 expanded. Four
configurations: Codex CLI 0.171.0 with `gpt-6.1-terra` and `gpt-6-luna` (reasoning
medium), and Claude Code 2.1.330 with `claude-sonnet-5-5` and `claude-haiku-5-5`
(effort medium). 5 randomized complete blocks gave 80 sequential attempts, each a
fresh session in a Seatbelt sandbox, evaluated independently in a clean checkout.

All 80 attempts completed. There were no timeouts, setup or infrastructure
failures, replacements, subagent use, out-of-scope changes, or test weakening.

## Primary outcome (frozen checks)

Primary success: completed session, all criteria AC01–AC11, and the original
regression suite.

| | D1 vague | D2 clarified | D3 agent-ready | D4 expanded |
|---|---|---|---|---|
| haiku | 1/5 | 4/5 | 5/5 | 5/5 |
| luna | 0/5 | 4/5 | 5/5 | 5/5 |
| sonnet | 0/5 | 5/5 | 5/5 | 5/5 |
| terra | 0/5 | 5/5 | 5/5 | 5/5 |

- Almost the entire effect is D1 → D2. Most D1 failures were behaviors D1 never
  specified: wildcard handling, the search form, the empty state.
- No attempt in any condition let a customer see another account's orders.
- D3 vs. D4 is 20/20 each. Their equivalence review was not recorded before
  freezing, so no verbosity conclusion is drawn.
- Agent time and tool use varied more by configuration than by description. The
  median agent time ranged from about 25–57 s (Sonnet) to 50–100 s (Luna).

## Evaluator limitations found after collection

The checks were frozen before collection, so the table above is the primary result.
Two limitations surfaced when the failures were inspected:

1. **Empty-state check (AC09) false negatives.** Seven attempts set a search-specific
   message through DataTables' `emptyTable` option. A browser shows it, but the check
   ignored `<script>` content. Counting those (post hoc) changes three cells: Haiku D1
   1/5 → 4/5, Haiku D2 4/5 → 5/5, and Terra D1 0/5 → 1/5. Haiku D2's only failure,
   reported as an explicit violation, is one of these. The other 12 empty-state
   failures are genuine: those attempts left DataTables' original “No orders yet.”
2. **Server-side assumption in the minimal outcome.** Three Terra D1 attempts built a
   client-side shareable search. `?q=` seeds DataTables' browser search, and the URL
   tracks it. That works in a browser and is a reasonable reading of D1, but it
   fails the frozen minimal outcome, which requires server-side filtering.

The one remaining explicit violation is genuine. Luna D2 escaped the backslash after
`%` and `_`, doubling every escape, so `%` searches matched nothing.

## Why the task was retired

Ridgeline already had a browser-side search box on the same table. A vague request
for “search with a shareable URL” can therefore be met client-side or server-side,
and the empty-state message can live in either layer. That overlap, not the
description treatments, explains part of the D1 variation. The next workload,
**Reorder a past order**, has no such overlap.

## Limits

One task, one host, five repeats per cell: exploratory. Cross-provider differences
include harness behavior (system prompts, tools, context management), not only
model quality. Token counts are CLI-reported. Claude Code's cost field is a CLI
estimate, not a charge.
